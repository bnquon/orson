# Demo event contract

This contract defines the fixed order flow used to build and demonstrate Orson. It describes what the demo services must publish and what Orson should display. It is not a restriction on payloads users may publish in their own scenarios.

## Flow

```text
order.created
├── total <= 500 → payment.charged
│                  ├── inventory.reserved
│                  └── notification.sent
│
└── total > 500  → order.cancelled
```

The payment service owns the branch decision. A cancelled order does not emit `payment.charged`, `inventory.reserved`, or `notification.sent`.

## Kafka conventions

- Every record uses JSON for its payload.
- Every record uses `orderId` as its Kafka key.
- Every record has a `content-type` header with the value `application/json`.
- Every record has an `x-correlation-id` header.
- Downstream services copy `x-correlation-id` unchanged from the record they consume.
- IDs are opaque strings. Consumers must not parse meaning from them.
- Currency values use uppercase ISO 4217 codes such as `CAD`.
- `total` is a number in whole currency units for this demo.
- Kafka record timestamps are the authoritative event timestamps for the MVP.
- Unknown JSON fields must be ignored so the contract can grow without breaking consumers.

Orson generates a fresh `x-correlation-id` for every run. The JSON fixtures contain only root payloads, so the publisher is responsible for adding the Kafka key and headers.

## Branch rule

The demo payment service evaluates `order.created.payload.total`:

- `total <= 500` produces `payment.charged`.
- `total > 500` produces `order.cancelled` with reason `payment_declined`.

The threshold is intentionally deterministic so the same payload always produces the same flow.

## `order.created`

Producer: Orson or the manual demo publisher  
Consumer: payment service  
Kafka key: `orderId`

```json
{
  "orderId": "ord_123",
  "customerId": "cus_123",
  "customerEmail": "developer@example.com",
  "currency": "CAD",
  "total": 279,
  "items": [
    {
      "sku": "orson-mug",
      "quantity": 1
    }
  ]
}
```

Required fields:

- `orderId`: non-empty string
- `customerId`: non-empty string
- `customerEmail`: non-empty string
- `currency`: three-character uppercase string
- `total`: non-negative number
- `items`: non-empty array
- `items[].sku`: non-empty string
- `items[].quantity`: positive integer

## `payment.charged`

Producer: payment service  
Consumers: inventory service and notification service  
Kafka key: `orderId`

```json
{
  "orderId": "ord_123",
  "paymentId": "pay_123",
  "amount": 279,
  "currency": "CAD",
  "status": "charged",
  "customerEmail": "developer@example.com",
  "items": [
    {
      "sku": "orson-mug",
      "quantity": 1
    }
  ]
}
```

Required fields:

- `orderId`: copied from `order.created`
- `paymentId`: non-empty string generated by the payment service
- `amount`: copied from `order.created.total`
- `currency`: copied from `order.created.currency`
- `status`: always `charged`
- `customerEmail`: copied from `order.created.customerEmail`
- `items`: copied from `order.created.items`

## `inventory.reserved`

Producer: inventory service  
Consumer: none in the demo  
Kafka key: `orderId`

```json
{
  "orderId": "ord_123",
  "reservationId": "res_123",
  "items": [
    {
      "sku": "orson-mug",
      "quantity": 1
    }
  ]
}
```

Required fields:

- `orderId`: copied from the correlated order
- `reservationId`: non-empty string generated by the inventory service
- `items`: copied from `payment.charged.items`

## `notification.sent`

Producer: notification service  
Consumer: none in the demo  
Kafka key: `orderId`

```json
{
  "orderId": "ord_123",
  "notificationId": "ntf_123",
  "channel": "email",
  "recipient": "developer@example.com",
  "template": "order-confirmation"
}
```

Required fields:

- `orderId`: copied from the correlated order
- `notificationId`: non-empty string generated by the notification service
- `channel`: always `email` in the demo
- `recipient`: copied from `payment.charged.customerEmail`
- `template`: always `order-confirmation`

## `order.cancelled`

Producer: payment service  
Consumer: none in the demo  
Kafka key: `orderId`

```json
{
  "orderId": "ord_456",
  "reason": "payment_declined",
  "total": 799,
  "currency": "CAD"
}
```

Required fields:

- `orderId`: copied from `order.created`
- `reason`: always `payment_declined` in the demo
- `total`: copied from `order.created.total`
- `currency`: copied from `order.created.currency`

## Service ownership

| Service      | Consumes          | Produces                               |
| ------------ | ----------------- | -------------------------------------- |
| Payment      | `order.created`   | `payment.charged` or `order.cancelled` |
| Inventory    | `payment.charged` | `inventory.reserved`                   |
| Notification | `payment.charged` | `notification.sent`                    |

Services must produce exactly one record for each transition they own. Retry and duplicate-delivery behavior can be added after the basic demo is working.
